# Cyberforteca 0.32 - Authority and Binding Hardening

Public development version: **Cyberforteca 0.3**.
Internal implementation revision: **0.32**.

This hardening revision patches the original 0.31 `cyberforteca` package.
It preserves its immutable nominal models, exact-scope policy evaluator,
session/channel split, decision re-evaluation, and deterministic serializer.
The original 0.31 archive and separate Terra build were left unchanged.
The review's `TrustedSnapshot` and `decisions.jsonl` identify this baseline.
It uses Python 3.10+ and the standard library, with no OS-specific dependencies.
The architecture contract, not Python, is the migration boundary.

**This is not production security software.** No hardware identity proof,
attestation verification, secure session handshake, credential verification,
encrypted transport, or actual resource enforcement is implemented. Test
fixtures explicitly supply simulated verification results. No successful
verifier stub is substituted for those missing systems.

## Run

From this directory:

```sh
python3 -m unittest discover -v
python3 tools/check_mutations.py
python3 -m examples.decisions
```

The example prints synthetic AUTHORIZED, RESTRICTED, DENIED, and recovery
decisions. Every example reports enforcement as NOT_ATTEMPTED. It uses only
synthetic references and contains no real personal or biological data.

To reproduce pre-fix failures with the original 0.31 project available:

```sh
python3 tools/check_pre_fix.py --baseline ../cyberforteca-0.31
```

That command expects twelve probes to fail by assertion, with no runtime errors.
It exits successfully only when the expected pre-fix failures are observed.
The same twelve probes pass as part of the ordinary 0.32 test suite.

Validated with Python 3.12.14: **84 tests pass**, all **4/4 targeted mutants**
are caught, and all **12 pre-fix probes** fail against original 0.31 with
19 assertion failures and zero errors. Full command output is in TEST_RESULTS.txt.
Capture a new report with `python3 tools/validate.py --baseline ../cyberforteca-0.31`.

4. `cyberforteca/interfaces.py`: future adapter contracts.
5. `cyberforteca/simulation.py`: deliberately simulated policy evaluation.
6. `cyberforteca/smc.py`: permanent skeleton and owner-cache purge simulation.
7. `docs/TEST_MATRIX.md`: preserved tests, regression probes, and mutation evidence.
8. `docs/PRESERVATION_02.md`: unchanged historical 0.2 source review.

`examples/decisions.jsonl` and `examples/decisions.log` are reproducible snapshots
generated by the example. JSON is the complete structured representation.
The human-readable log is a concise projection, not an alternative authority.

## Preservation status

The prior 0.31 review covered two available 0.2 source documents without modification.
They begin partway through the implementation, so this is an additive reference
package, not a claim that a complete 0.2 repository has been patched or regression
tested. Integration with the complete original source remains pending.

## Implemented versus specified

Implemented at model/simulation level: keyword-only security records, bound
identity results, handshake freshness, closed fallback relation, ungrantable
audit deletion, epoch-bound grants and use-time checks, separate owner and
recovery verification, enforced registry bindings, narrow ownership restoration,
policy-owned recovery ceilings, explicit local/peer audit attribution, SMC split,
owner-authorized cache purge receipts, deterministic CF032 JSON and snapshots.

Specified only: secure provenance, device/app measurement verification, lifecycle
event handling, non-reusable session creation, protected grant registry,
production grant revocation and enforcement, atomic policy snapshots, ownership
proof verification, persistent audit sequence allocation, transactional cache
erasure, and protected hash-chained audit storage. The SMC simulation only
removes metadata from a returned immutable in-memory state, never user files.

No dependency on secrecy is assumed. The source, formats, decision rules, and
enforcement contracts are intended to remain understandable to an attacker.
